INTELLIGENT TIMETABLE MANAGEMENT SYSTEM
MODEL TRAINING + TIMETABLE GENERATION (PROTOTYPE)
=================================================

WHAT IS INCLUDED
----------------
- train_and_schedule.py: trains the ranking model and generates two schedules.
- reference_placement_ranker.joblib: fitted scikit-learn pipeline.
- model_evaluation.json: holdout metrics for the reference-placement target.
- test_predictions.csv: predictions for held-out classes.
- timetable_baseline.csv: schedule generated by the non-ML heuristic.
- timetable_ml.csv: schedule generated by the ML-guided heuristic.
- scheduler_comparison.csv: side-by-side scheduler metrics.
- independent_overlap_validation.csv: recomputed room/instructor overlap checks.
- scheduler_evaluation.json: full machine-readable summary.

INPUTS EXPECTED
---------------
The scripts resolve paths relative to their location by default:
- unitime_cleaned/
- unitime_validation_stage/candidate_placement_features.csv
- unitime_model_scheduler/

You can also override the root directory by setting the UNITIME_ROOT
environment variable if desired.

RUN
---
Activate the local virtual environment (or install requirements):
  source ../../.venv/bin/activate
  pip install -r ../../requirements.txt
Then run:
  python train_and_schedule.py

MODEL TARGET AND INTERPRETATION
-------------------------------
The model target is whether an exact class-room-time candidate appears in the
committed UniTime reference solution. It is a ranking proxy, NOT a true
conflict label. An unselected candidate is not necessarily invalid or poor:
many timetables can be feasible. Therefore, test ROC-AUC/average precision
measure ability to identify reference-selected placements, not general
timetable quality or performance on another university.

Data split is grouped by class_id so candidate rows for one class do not cross
train/validation/test. Approximate proportions are 65/15/20. Because the data
comes from one benchmark instance and one reference solution, generalization
claims must remain limited.

SCHEDULER
---------
The baseline uses room/time preference cost. The ML-guided version ranks
candidates using model score with preference tie-breaks. Both use greedy
assignment and enforce weekly room and instructor overlap checks. Shared
student overlaps are estimated from student-offering data and treated as a
soft proxy cost. Current implementation does NOT fully enforce UniTime group
constraints, date-specific exceptions, all room-sharing rules, or all
multi-room semantics. It is not an optimal solver and not a full UniTime clone.

CURRENT RUN RESULTS
-------------------
See scheduler_comparison.csv and scheduler_evaluation.json for measured results.
This run scheduled fewer than all 896 classes in both configurations; unassigned
classes are listed in scheduler_evaluation.json. Zero room/instructor overlap
pairs were found in the generated schedules. This does not mean every UniTime
hard constraint is satisfied.

INTERPRETATION
--------------
Do not claim that the system has solved the entire benchmark. Present it as a
working prototype that:
1) trains a supervised placement ranker,
2) generates partial feasible schedules under the implemented hard checks,
3) compares an ML-guided greedy heuristic against a non-ML baseline, and
4) reports unsupported constraints and remaining unassigned classes honestly.

NEXT ENGINEERING STEP
---------------------
Improve the scheduler with backtracking/repair or a constraint-programming solver,
implement and test group constraints and date-specific meetings, then rerun
the independent validator. Only after that should the project claim full
timetable generation.
